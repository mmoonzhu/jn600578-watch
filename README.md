# 京能电力（600578.SH）定增公告 → 邮件自动提醒

一旦京能电力披露与**定向融资/向特定对象发行A股（定增）**相关的公告，自动发邮件通知你。

- **数据源**：东方财富公告 + 巨潮资讯网（法定披露网站），双源交叉校验，任一源挂掉仍能工作
- **去重**：按公告标题去重，同一份公告只发一次；已发的记进 `state.json`，重启也不重复
- **凭据安全**：邮箱地址和授权码只存在 GitHub Secrets（加密存储，日志显示为 `***`），**不写进任何文件、不进代码仓库**
- **失败必现**：发信失败时脚本以退出码 1 结束，GitHub Action 会变红并给你发告警邮件，不会出现"显示成功但没发出去"

---

## 第 1 步：拿到邮箱 SMTP 授权码

以 QQ 邮箱为例（163 / Gmail 同理，见下表）：

1. 打开 QQ 邮箱网页版 → **设置** → **账户**
2. 往下找到「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」
3. 开启 **IMAP/SMTP 服务**（会让你用手机发短信验证）
4. 验证通过后页面会给出一串 **16 位授权码** —— 复制保存

> ⚠️ **授权码 ≠ 邮箱登录密码。** 脚本里 `EMAIL_PASS` 必须填授权码，填密码会报「SMTP 认证失败」。

| 邮箱 | EMAIL_HOST | EMAIL_PORT |
|---|---|---|
| QQ 邮箱 | `smtp.qq.com`（默认，可不填） | `465`（默认，可不填） |
| 163 邮箱 | `smtp.163.com` | `465` |
| Gmail | `smtp.gmail.com` | `587`（自动用 STARTTLS） |
| Outlook | `smtp.office365.com` | `587` |

### 想让邮件在微信里弹通知？（免费，不需要任何付费服务）

既然各路微信推送服务都要收费或实名，最省事的办法是让**微信替你盯着邮箱**：

- **QQ 邮箱**：微信搜索公众号「**QQ邮箱提醒**」→ 关注并绑定邮箱 → 打开提醒开关。新邮件到达时微信直接弹通知。
- **QQ 邮箱以外的邮箱**：可以在 QQ 邮箱里设置「**其他邮箱**」收信，再走上面的提醒（设置 → 其他邮箱 → 添加）。

这样效果等同于推到微信，且**完全免费、无需实名**。

## 第 2 步：把邮箱填进 GitHub Secrets（不要写进文件）

仓库页面 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| Secret 名 | 必填 | 值 |
|---|---|---|
| `EMAIL_USER` | ✅ | 发件邮箱完整地址，如 `123456@qq.com` |
| `EMAIL_PASS` | ✅ | SMTP **授权码**（16 位，不是登录密码） |
| `EMAIL_TO` | 可选 | 收件地址，**发给自己留空即可**；多个用逗号分隔 |
| `EMAIL_HOST` | 可选 | 默认 `smtp.qq.com`，非 QQ 邮箱按上表填 |
| `EMAIL_PORT` | 可选 | 默认 `465`（SSL）；`587` 自动改用 STARTTLS |
| `DAILY_HEARTBEAT` | 可选 | 默认 `1`（每天一封「监控正常」）。不想收就设为 `0` |

> Secrets 是加密存储的，日志里自动打码成 `***`，改不了也读不回去，只能覆盖。
> **本地因此不需要 `config.json`**。

**本地运行**（可选）：不想用文件就直接传环境变量，
或者 `cp config.example.json config.json` 后填进去 —— `config.json` 已被 `.gitignore` 排除，不会误提交。

## 第 4 步：验证收得到

仓库 → **Actions** → 左侧选「京能电力定增公告监控」→ 右上角 **Run workflow** 手动跑一次。

跑完你应该收到两封邮件：

1. **《【京能电力】公告监控已启动》** —— 首次运行自动建基线时发的，里头会告诉你当前最新一条定增公告是什么
2. 之后每天一封 **《【京能电力】监控正常 · 日期》** —— 用于确认任务真的在执行

也可以先在本地自测：

```bash
EMAIL_USER=你的邮箱@qq.com EMAIL_PASS=授权码 python3 watch.py --test
```

**没收到邮件就一定还没通。** 常见报错对照：

| 报错 | 原因 |
|---|---|
| `SMTP 认证失败` | `EMAIL_PASS` 填了登录密码而不是授权码 |
| `SMTP 发送失败 ... Connection refused / timed out` | 端口不对。465 用 SSL，587 用 STARTTLS，别混 |
| `未配置推送通道` | `EMAIL_USER` / `EMAIL_PASS` 至少有一个没填到 Secrets |
| 中文标题乱码 | 已处理（RFC 2047 编码），如遇异常请提 issue |

## 设置自动定时运行（三选一）

> ⚠️ **只选一个方案。** 多处同时写 `state.json` 会互相覆盖，导致漏发或重复发。

### 方案 A：GitHub Actions —— 真·云端，电脑关机也照跑（推荐）

`.github/workflows/ann-watch.yml` 已配好，推上去即自动生效，无需改动。

- **检查时间**：北京时间 **09:07 和 21:07**（UTC `7 1,13 * * *`），刻意避开整点——GitHub 在整点负载高会推迟执行
- 分别覆盖**盘前**和**盘后**两个公告披露高峰
- **成本**：免费额度每月 2000 分钟，本方案每月约用 300~700 分钟

**即使某次定时被 GitHub 跳过也不会漏**：因为有 `state.json` 去重，未发过的公告仍在 30 天回溯窗口内，下次运行会补发。这正是有状态方案的关键优势。

改频率：编辑 workflow 里的 `cron`（UTC 时间，北京时间减 8 小时）。

**已知局限**：负载高峰时可能延迟几分钟到几十分钟。定增公告不是抢秒级行情，晚几十分钟无妨。

---

### 方案 B：macOS 原生定时器 —— 本地常驻，最及时

```bash
cp com.jndl.annwatch.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.jndl.annwatch.plist
```

- 默认**每小时**一次，开机自动启动
- 查看是否在跑：`launchctl list | grep jndl`
- 停止：`launchctl unload ~/Library/LaunchAgents/com.jndl.annwatch.plist`
- 改频率：编辑 plist 里的 `StartInterval`（秒，3600 = 1 小时）

**前提：电脑要开机**（合盖睡眠会暂停）。此时凭据放本地 `config.json`，只存在你自己的磁盘上。

---

### 方案 C：WorkBuddy 定时任务（已暂停，不推荐）

自动化任务已设为**暂停**——它和方案 A 会同时写 `state.json` 造成冲突。

它本身的局限：绑定本地工作目录，脚本和 `state.json` 都在本地磁盘。若改用**云端沙箱**执行，读不到本地文件，且沙箱任务结束即销毁、`state.json` 无法留存 → 每次都从头建基线，永远推不出新公告。

要用它请先停掉方案 A。

---

### 附：无状态版 `watch_cloud.py`（备用）

给「跑完即销毁」的沙箱环境准备，**完全不读写 `state.json`**，改用「回溯最近 N 天的发布日期」判断新旧。

```bash
EMAIL_USER=xxx EMAIL_PASS=yyy WINDOW_DAYS=2 python3 watch_cloud.py
EMAIL_USER=xxx EMAIL_PASS=yyy python3 watch_cloud.py --dry
```

**为什么不默认用它**：实测两个数据源的公告时间都只精确到**日期**（巨潮的时间戳统一是 `00:00:00`），做不了「最近几小时」的精细窗口。没有状态就无法既保证不漏又保证不重复——窗口开大会重复发，窗口缩小则某次被跳过就永久漏。

结论：**能存状态就存状态**（方案 A/B）。

打开 `watch.py` 顶部的两个列表：

- `KEYWORDS` — 命中任一即推送。默认覆盖定增全流程：预案、论证分析、问询回复、审核通过、同意注册、发行结果、上市公告书等

## 常见问题

**会不会重复发？**
不会。每份公告发一次后记入 `state.json`，后续自动跳过。

**每天那封「监控正常」能关掉吗？**
GitHub Secrets 里加 `DAILY_HEARTBEAT` = `0`。默认开着是为了让你确认任务真的在跑——
GitHub Action 全绿并不代表真的执行成功了，这封邮件就是凭据。

**为什么 GitHub 显示成功却没收到邮件？**
现在不会了。推送失败会让 job 变红，GitHub 还会给你发一封失败告警邮件。

**误报/漏报？**
改 `KEYWORDS` / `EXCLUDE`，改完 push 上去立刻生效，不用重启定时器。

**我的邮箱会被泄露吗？**
不会。邮箱只存在 GitHub Secrets（加密、不可读取、日志打码），脚本还会在日志里把地址脱敏成
`t***r@qq.com`。仓库建议保持 **Private**。
